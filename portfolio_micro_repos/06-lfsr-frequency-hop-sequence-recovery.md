# LFSR Frequency-Hop Sequence Recovery & State Reconstruction

> **tl;dr:** A military tactical radio uses a 20-bit Fibonacci Linear Feedback Shift Register (LFSR) coupled with a non-linear mixing filter to select hop channels across an 80-channel grid. Given sparse, noisy RF detections contaminated by co-channel clutter from adjacent units, this repo shows how to recover the exact 20-bit initial LFSR state and deterministically predict future hop channels using both Python and high-performance C solvers.

## 1. The Engineering Problem

Frequency-Hopping Spread Spectrum (FHSS) systems resist intentional jamming and passive interception by rapidly switching carrier frequencies across a wide RF band according to a pseudo-random pattern. An Electronic Support Measures (ESM) receiver monitoring a tactical battlespace collects automated RF energy bursts over time:

- Intercept log: `data/detections.csv` containing detection timestamps `t_s` and tuned channel IDs.
- Watchlist: `data/watchlist.txt` containing the subset of authorized channels monitored by the intercept sensor.

However, operational conditions introduce two critical real-world impairments:
1. **Missed Hops**: Atmospheric fading and receiver dwell-time gaps cause missing hop observations.
2. **Co-Channel Clutter**: A neighboring friendly detachment operating on the same frequency band creates spurious detections that do not belong to the target transmitter.

The signals intelligence objective is to identify the underlying pseudo-random generator, reconstruct the transceiver's **exact initial 20-bit state ($s_0$)**, and predict the next 12 consecutive hop channels ($k = 1000$ to $1011$) to enable synchronized follower jamming or full decryption.

---

## 2. Why Naive Approaches Fail

1. **Direct Berlekamp-Massey Breakdown**: The standard Berlekamp-Massey algorithm reconstructs an LFSR's minimal polynomial in $\mathcal{O}(L^2)$ time given $2L$ consecutive linear output bits. Here, the raw LFSR bits are never transmitted directly; they are filtered through a **non-linear mixing function** combining bitwise XOR, bit shifts, and arithmetic modulo 80. The non-linear algebraic degree destroys linearity, preventing direct Berlekamp-Massey application.
2. **Exact String / Substring Matching**: Seeking contiguous blocks of observed channels fails because missing hops break continuity, while false-positive detections from adjacent units introduce corrupt tokens into the stream.
3. **Pure Brute-Force without Hop Index Synchronization**: Attempting to align observed timestamps without establishing the discrete hop slot grid leads to phase ambiguity. The continuous timestamp $t$ must be mapped to a discrete integer hop slot $k$.

## 3. The Mathematical Foundation

### 3.1 Fibonacci LFSR State Dynamics

The generator is a 20-bit Galois-field feedback shift register operating in Fibonacci configuration. Its state at discrete time step $k$ is represented as an unsigned 20-bit integer:

$$s_k \in \{0, 1, \dots, 2^{20} - 1\}$$

The feedback bit $f_k \in \{0, 1\}$ is generated by XORing feedback taps at bit positions 19 and 16 (0-indexed from LSB):

$$f_k = (s_k \gg 19) \oplus (s_k \gg 16) \pmod 2$$

The state transition update function $\mathcal{T}(s_k)$ shifts the register left by 1 bit and inserts $f_k$ into the least significant bit (masked to 20 bits):

$$s_{k+1} = \mathcal{T}(s_k) = \left((s_k \ll 1) \mid f_k\right) \wedge \text{0xFFFFF}$$

This corresponds to the characteristic polynomial:

$$P(x) = x^{20} \oplus x^{17} \oplus 1 \in \text{GF}(2)[x]$$

### 3.2 Discrete Hop Grid Quantization

The transmitter operates on a fixed dwell time of $T_{\text{hop}} = 20\,\text{ms}$ ($0.02\,\text{s}$). For any observed event at timestamp $t_i$:

$$k_i = \left\lfloor \frac{t_i}{T_{\text{hop}}} + 0.5 \right\rfloor = \text{round}\left(\frac{t_i}{0.02}\right)$$

This maps arbitrary floating-point timestamps onto exact discrete hop indices $k \in \mathbb{N}_0$.

### 3.3 Non-Linear Channel Filter

The 20-bit internal state $s_k$ is decomposed into three overlapping bitfields:

$$t_1 = s_k \wedge \text{0x7F} \quad (\text{bits } 0..6)$$

$$t_2 = (s_k \gg 7) \wedge \text{0x7F} \quad (\text{bits } 7..13)$$

$$t_3 = (s_k \gg 14) \wedge \text{0x3F} \quad (\text{bits } 14..19)$$

The output channel index $C(s_k) \in \{0, 1, \dots, 79\}$ is produced by:

$$C(s_k) = \left((t_1 \oplus t_2) + (t_2 \cdot t_3)\right) \pmod{80}$$

### 3.4 Maximum-Likelihood State Recovery over Noisy Data

Because the register width is $L = 20$ bits, the total state space is bounded:

$$|\mathcal{S}| = 2^{20} = 1,048,576$$

Rather than solving complex non-linear algebraic equations over $\text{GF}(2)$, we formulate a **maximum-likelihood scoring function** robust to missing hops and clutter.

Let $\mathcal{D} = \{(k_i, c_i)\}_{i=1}^M$ be the set of observed (hop index, detected channel) pairs. For each candidate seed $s_0 \in [1, 2^{20}-1]$:

$$\text{Score}(s_0) = \sum_{i=1}^M \mathbb{I}\left(C\left(\mathcal{T}^{k_i}(s_0)\right) == c_i\right)$$

where $\mathbb{I}(\cdot)$ is the indicator function. The true initial state $s_0^*$ maximizes this match score:

$$s_0^* = \arg\max_{s_0 \in \mathcal{S}} \text{Score}(s_0)$$

Because false clutter detections are distributed across unrelated channels, the true seed exhibits a dramatic score spike ($\sim 95\%$ consistency with target detections), while spurious candidates score near noise floor ($\sim 1/80 \approx 1.25\%$).

## 4. Algorithmic Breakdown

1. **Data Ingestion & Quantization**:
   - Parse `detections.csv`.
   - Calculate $k = \text{round}(t / 0.02)$ for each row.
   - Filter to keep detections whose channels exist in the monitored watchlist.
2. **State Simulation**:
   - Precompute or simulate on the fly the Fibonacci step $\mathcal{T}(s)$.
3. **Candidate Scoring Engine**:
   - Iterate over all candidate seeds $s_0 \in [0, 1048575]$.
   - Step state forward and evaluate match against observed $(k, c)$ pairs.
   - Retain candidate with highest match count.
4. **Sequence Extrapolation**:
   - Initialize state with optimal seed $s_0^* = 648113$.
   - Step forward $k = 0 \to 1011$.
   - Record and output predicted channels for $k \in [1000, 1011]$.

## 7. Setup & Execution

### Running the Python Solver

```bash
git clone https://github.com/<your-username>/lfsr-frequency-hop-sequence-recovery.git
cd lfsr-frequency-hop-sequence-recovery
pip install -r requirements.txt
python solve.py
```

### Compiling and Running the Fast C Solver

For multi-threaded sub-second evaluation:

```bash
gcc -O3 -march=native -fopenmp solve.c -o solve_c
./solve_c
```
